# 会话压缩模板（config-template）—— session_compress_skill 的权威模板

> 本文件是 `session_compress_skill` 生成 `session.md` 的**唯一权威**模板。
> 用途：长会话"过程折叠成状态"——在里程碑把多轮业务上下文压缩成 `session.md`，然后**开新会话**由用户手动继承，避免输入 token 随历史线性膨胀。
> 生成：会话过长时触发 `session_compress_skill：`，按本模板结构写入工作目录下的 `session.md`。
> 属会话工作产物，非框架；可删可迁移。

## 标准结构（生成 session.md 时套用）

````markdown
# 说明：以下内容是上一个会话压缩后的历史上下文，为了避免输入 token 过大，新会话继承以下内容继续历史主题对话

## A. 历史会话主题
- <一句话主题，如 "NR PDCCH 配置链梳理">

## B. 历史会话目录
- 工作目录：`<绝对路径>`
- 资料目录：`<绝对路径，放参考文档/协议/语料>`
- 文件输出目录：`<绝对路径，放 HTML/产物>`

## C. 历史会话要点
- <结论1>：已核实的事实/机制
- <结论2>：

## D. 历史会话修改/输出文件
- `<输出文件1>` ← 说明
- `<输出文件2>` ← 说明

## E. 历史会话使用工具
- 工具1：
- 工具2：
````

## 使用规则

1. **只写业务类**：A 主题 / B 目录 / C 要点 / D 改输出文件 / E 工具——**全部为业务类内容**（本任务相关）。
2. **上下文不包括框架 skill**：框架 skill 的**讨论、修改、工具、进化**一律不写入 session.md。
3. **C 要点**：只收"已核实 + 已落地 + 用户确认"的结论，禁止未验证推测；用简短 bullet，可随时追加；只含本任务业务结论，不含框架 skill 讨论。
4. **D 文件**：列本次会话产生/修改的**业务输出文件**（HTML、md 等任务产物），**不列框架 skill 的改动文件**。
5. **E 工具**：只列实际使用过的业务工具名，不写操作步骤/方法；框架运营类工具（health_check、skill_validate 等）不写；**opencode 内置工具不写**。
6. **不写"下一步"**：交给新会话由用户按新需求提出，避免绑架新方向。
7. **继承方式**：新会话开头由**用户手动**粘贴本摘要全文（或引用文件），即可从业务结论继续，无需重读旧会话历史。

## 文件命名与位置

- 文件名固定：**`session.md`**
- 位置：当前任务的工作目录（提问所在目录）
- 覆盖规则：覆盖工作目录下已有的旧版 `session.md`
