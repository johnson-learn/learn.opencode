# 任务窗/任务跟踪执行技能（task_tracking_skill）

## 🛠 工具依赖清单

| 工具 | 用途 | 说明 |
|---|---|---|
| todowrite（opencode 内置工具） | 建立/更新/标记任务窗 | 零外部依赖，opencode 内置 |

无额外外部依赖；任务窗同步只用内置 todowrite 工具。校验脚本引用：`skill_validate.py` / `test_regedit.py` / `test_instructions.py`（改动后跑）。

## 职责

本 skill 是「任务窗强制」的**执行器**。AGENTS 铁律第 8 条（任务窗强制，动作化）每收到新要求必须同步任务窗，本 skill 承载该纪律的可执行流程。详版见 `<opencode配置目录>\instructions.md` 全局通用回答规则第 6 条「长任务执行节奏」之「任务窗强制」子点。

## 核心要求：实时更新

**实时更新**（本 skill 的第一性要求，解释"任务窗强制"为何有效）——定义如下：

> **任务窗条目列表中，每完成一个任务，立即用 todowrite 更新该条目对应的任务状态（in_progress → completed / 或推进到当前实际状态），逐条推进，直到任务窗全部条目 completed（或挂起项给出合理的 in_progress 说明）。**

- 实时 = **每完成一个任务就同步一次**（不是攒到结尾批量补、不是"想起来才标"）。
- 逐条推进 = 无论条目被分多少块、多少个子智能体承担，都按实际完成顺序逐条更新对应状态。
- 直至全清 = 任务窗随执行持续推进，最终收敛到全部 completed（挂起/取消项须明确标注并说明）。
- 一旦发现某条条目状态与事实不符（做了却没标/标了却没做），立即用 todowrite 纠正——实时更新以"清单与事实逐条一致"为验收标准。

## 处理流程（动作化，每步做完立即执行）

0. **收到新要求/新消息，第一步 = todowrite 建/更新窗**：为该要求建立对应任务项（内容简明、标 in_progress、设优先级）；**先建/更新窗再动工**，禁止"先做后补窗"或"收到要求却不建窗"。
1. **每个对话与每个新要求都必须有任务窗**：无任务窗不得直接开启大任务。
2. **任务量大用子智能体（task 工具）分担并行**：子智能体承担的任务也须纳入同一任务窗（作为任务项），其进展随主智能体同步。
3. **用户更新要求时（新增/删改/变更需求）同步更新主智能体与子智能体任务窗**：增删改任务项、调整状态/优先级，使列表始终与最新要求及事实进展一致。
4. **每完成一个任务，立即更新该条目状态（实时更新核心闭环）**：任务结束后立刻用 todowrite 把对应条目从 in_progress 改 completed（或推进到当前实际状态），**逐条推进，直到任务窗全部条目 completed**；分块/子智能体/里程碑同样适用——每完成一块即更新对应项，禁止创建后不管、禁止最后批量补标记、禁止"做了没标/标了没做"。有确实无法完成的条目→标 cancelled 或留 in_progress 并写明原因，不得悬空。
5. **收尾校验**：交付/里程碑结束时，自查任务窗——所有项应 completed 或处于合理的 in_progress；有悬空项需说明或补处理。

## 操作规范

- **每次 todo 项写法**：`{简明内容}` + `{状态: pending|in_progress|completed|cancelled}` + `{优先级: high|medium|low}`（agenda 简洁，避免超长描述）。
- **何时建**：每收到一条新消息/新要求（这是 hook，不是"想起来才建"）。
- **何时标**：每完成一步立即标（这是纪律，不是"最后补"）。
- **何时更新**：用户更新要求时；子智能体并行时；状态变化时。
- **子智能体**：为由 task 工具派发的子智能体建立的对应任务项也要纳入主任务窗统一跟踪（同窗合并，不另开）。

## 铁律

- **先建窗，再动工**（收到新要求第一步就建/更新任务窗，禁止先做后补窗）。
- **实时更新（铁律）**：每完成一个任务，立即用 todowrite 将该条目状态更新为 completed（或推进到实际状态），逐条推进直至任务窗全部条目 completed；禁止最后批量补标记、禁止创建后不管、禁止"做了没标/标了没做"。
- **每完成一步立即标记**（禁止最后批量补标记、禁止创建后不管）。
- **用户更新要求必须同步主+子智能体任务窗**（使任务列表始终与最新要求一致）。
- 禁止"无任务窗直接开启大任务"。
- 与 AGENTS 铁律第 8 条、instructions 第 6 条「长任务执行节奏」（同目标一轮连续完成、批量工具调用、里程碑才汇报、分块自闭环、超长会话开新会话）配合执行——任务窗是长任务节奏的落地载体。

## 自检（交付前/里程碑时）

- 任务窗是否覆盖了本会话每个新要求？有无"收到要求却没建窗"的漏项？
- 每个已完成任务项是否都标 completed？有无 in_progress 但长期未动（需说明）？
- 用户最近的更新要求是否已同步到任务窗（含子智能体项）？
- 若发现漏同步，立即用 todowrite 补齐，不得留到应答后。
