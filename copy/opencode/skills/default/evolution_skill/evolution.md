# 进化规则（Evolution Rules）—— 现行进化规则权威文件

> **本文件定位**：本文件只承载**现行有效的规则与机制**（LLM 执行依据，不含历史注记）；**历史流水在 evolution_log.txt**（只增不改、追加记录、不做决策、仅供参考）。
> **更新本文件的强制流程**：① 结合 evolution_log.txt 内容核对（新规则与历史教训不矛盾）；② **弹窗让用户确认**
> （question 工具）是否更新；③ 确认后才 edit 本文件；④ 更新后跑 test_evolution_consistency.py。

## 现行进化规则（按规则主题组织；历史版本见 evolution_log.txt 流水）

### 进化固化流程

1. **六步固化流程**：第一步·归纳 → 第二步·归属 → 第三步·确认 → 第四步·edit → 第五步·流水 → 第六步·校验；每步强制输出【第X步·XX】标记行，gate --check-5step（参数名保留历史名）程序化检测，缺步即告警。**第三步·确认**：任何经验写入进化相关文件（rules/skill/evolution.md/regedit.md 等）前必须用 question 工具弹窗让用户逐条选择：① 同意（按模型方案写入）② 填写内容（用户修改后写入）③ 跳过（仅流水记"用户跳过"）；用户未确认前不得 edit；**任何非用户明确要求的文件修改（含判定四条件不满足的事实类流水追加）均须先弹窗确认**
2. **固化判定四条件**：① ≥2 个不同场景出现（或 1 个场景但踩坑代价高/用户点名）② 可移植 ③ 不与已有规则重复 ④ 能写出触发条件与适用边界——任一不满足 → 只追加 evolution_log.txt（事实类），不写规则文件；第一步必须显式输出结论行【判定四条件】场景数：X / 可移植：是 / 无重复：是 / 边界：明确（程序化检测项）
3. **进化门禁机制（evolution_gate.py）**：机制步骤（流水兜底追加/自动测试/一致性校验/配套漏更检测/新增删除文件检测/六步检查点检测/经验健康引擎）由脚本确定性执行——插件 session.created 调 --snapshot/--drain、session.idle 调 --check、固化标记由 --check-5step 检测；模型只负责智能部分（经验归纳/归属判定/弹窗确认/edit 固化）
4. **进化触发双机制**：AGENTS.md 铁律第 2 条（每次响应复盘进化，14 类触发）主 + 插件 session.idle 兜底注入（幂等去重）

### 用户决策与确认

5. **弹窗决策统一铁律**：凡需用户决策的环节一律 question 工具弹窗（禁止文字提醒/文字建议代替）——覆盖：① 合并/拆分/迁移=进化整理建议后弹窗让用户决策（执行/不执行/填写修改方案）② 规则冲突裁决=整理「冲突裁决建议」后弹窗（按新验证结果修订/保留旧规则/填写方案）③ 付费 API/凭证使用前弹窗征得同意 ④ update_skill 同步冲突/资产提取建议/网络失败询问等全部弹窗化
6. **门限触顶弹窗决策**：任何门限值（注入量上限/SKILL.md 体积门限/裸声明告警阈值等）一旦到门限值，必须 question 工具弹窗让用户选择——① 修改门限（填写新值，同步更新所有引用该门限的文件与测试）② 沿用原门限（按原门限继续精简/整改），禁止模型擅自改门限值或擅自突破
7. **文件修改弹窗确认铁律**：任何非用户明确要求的文件修改（含事实类流水追加、恢复/删除操作）必须先经 question 工具弹窗确认，禁止未经确认先斩后奏；旧条款"判定四条件不满足的纯流水追加不弹窗"已废止

### 框架机制

8. **注册事件注入（E 类平台直读）**：opencode 1.18 系列不消费 instructions 字段（实测：解析进配置但系统提示构建只认 AGENTS.md/CLAUDE.md/CONTEXT.md）；平台注入通道=skill-banner 注册 experimental.chat.system.transform（每次请求构建系统提示时直读 instructions/regedit/docs-sync/tools-manifest 四文件注入 output.system，mtime 缓存，OPENCODE_DISABLE_MD_INJECT=1 禁用）；默认把 output.system 全部元素合并为单条 system（平台内置 → 注入文件 → 语言指令顺序拼接）——Qwen 等 vLLM 严格校验「system 必须恰好一条且位于开头」的兼容适配，OPENCODE_SYSTEM_MERGE=0 回退 push 模式
9. **平台 API 依赖保障**：experimental.chat.system.transform 是实验性 API——test_platform_api.py 硬检查二进制 hook 实现存在性，health_check 第⑦项必跑，插件 session.created 异步检测失败即 toast 告警；失效回退预案：重启 instructions 字段（若新版实现）→ 铁律第 0 条 B 类路径
10. **experimental API 使用前提**：opencode 配置字段"被解析≠被消费"——必须用 debug config + 二进制字符串证据 + 新对话实测三段法核实后才可依赖
11. **语言跟随裁定规则**：语言跟随的唯一权威依据=当条消息实际语言（思考/回答/输出三者一致跟随）；平台语言指令（【语言指令·平台检测】）只是会话默认基调兜底，与当条消息冲突或平台检测失效时一律以当条消息实际语言为准（规则兜底写入 instructions.md 第 1 条裁定条款）
12. **进化质量与可持续性**：① 固化判定四条件——不满足只记流水事实类；② 经验状态标记（active/deprecated/invalidated，只追加标记不删改历史）；③ 重要经验二次验证（标待二次验证→下次任务验证→记结果）；④ 注入量管控（四注入文件合计上限 70KB；触顶时弹窗让用户选改门限或沿用）；⑤ 使用率自审（约 10 次会话未被提及→提示下沉/标 deprecated）；⑥ 冲突显式裁决（禁止静默二选一，响应中标注并同步改旧条目；弹窗决策）

### 同步与规范

13. **同步边界铁律**：只有显式 update_skill 才允许 git 同步动作
14. **五步同步框架**：吸收远端→修改→自测（缺用例先补写，双向更新用例须模拟远端）→弹窗确认→按选择执行
15. **对端修改评审**：pull 到对端新提交后逐 diff 评审；不合理则回退+注释（commit/时间/回退原因三要素）
16. **提交前可移植性校验**：待提交内容不得含本机特征（home 真实路径/用户名路径/本机特有绝对路径）
17. **同步过滤规则**：判断标准=其它机器使用框架/skill/功能时需要的才同步；临时文件由 .gitignore 自动过滤
18. **项目资产盘点**：同步前遍历项目提取通用资产到全局（拿不准的列建议清单）
19. **本文件定位**：进化规则文件（非历史流水）；历史流水独立于 evolution_log.txt
20. **evolution_log.txt 只增不改**：追加尾部，禁止替换既有条目
21. **弹窗确认**：update_skill 第五步前强制（question 工具弹窗，禁止文字提问代替；未确认前禁 commit/push）
22. **修改复盘核查**：每个文件修改完成后、自测前强制自查（改了什么/应改载体是否全改/占位符可移植性/配套文档）
23. **归属二分铁律**：规则/流程/机制类经验必须写入可执行载体（SKILL.md/instructions.md/regedit.md/AGENTS.md/本文件），只写 evolution_log.txt = 归属失败；记录/事实类才仅写历史流水
24. **测试先行**：每次修改必须跑对应测试；新增机制必须同步新增测试用例并更新 tests/README.md
25. **SKILL.md 体积门限可配置**：默认 8KB，超限待决清单三选一（改门限/忽略/忽略全部），skill_validate_config.json 持久化
26. **注册表机制**：regedit.md 全体系组件加载方式登记（A~H 八分类），组件变更必须同步更新并跑 test_regedit.py
